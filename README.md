# agent-ai-tool

A directory of tools an AI agent can actually connect to, published at
[agent-ai-tool.com](https://agent-ai-tool.com).

Each entry names the endpoint an agent should call, plus the agent card and MCP
endpoint when the service publishes them. The whole directory is available in
one machine-readable fetch at `/agents.json`.

The site is generated by a stdlib-only Go program. There is no frontend
toolchain, no bundler, and no runtime service: the generator writes static
files and GitHub Pages serves them.

## Layout

```
main.go                    flags, wiring, and the degradation report
internal/content/          curated entry schema, strict validation
internal/live/             vtessera feeds, snapshot cache, validators
internal/render/           templates, discovery artifacts, robots policy
content/entries/*.json     curated listings, one file each
content/live-*.json        committed snapshots of the vtessera feeds
assets/                    logo and stylesheet, copied verbatim
public/                    generated; do not edit or commit
```

The three units are independent, which is what keeps the test suite honest:
`content` never learns about HTTP, `live` never learns about HTML, and `main.go`
is the only place they meet.

## Commands

```bash
make            # fmt, vet, test, build
make test       # unit and end-to-end tests, including -race
make generate   # render public/
make serve      # generate, then serve on :8080
```

`TMPDIR` is set by the Makefile. `/tmp` is a tmpfs and counts against RAM.

## Adding a curated entry

Drop a JSON file in `content/entries/`:

```json
{
  "slug": "some-tool",
  "name": "Some Tool",
  "summary": "One sentence on what it does and when to reach for it.",
  "url": "https://example.com",
  "agent_card_url": null,
  "mcp_endpoint_url": null,
  "category": "text",
  "access": "free tier available",
  "source": "curated",
  "last_verified": "2026-09-27T00:00:00Z"
}
```

Validation is strict on purpose. Unknown fields are rejected rather than
ignored, duplicate slugs fail the build, and URLs must be absolute `http` or
`https`. A mistyped field should stop the build, not ship as a blank on the
page. `agent_card_url` and `mcp_endpoint_url` are optional; use `null` or omit
them. `category` and `access` are optional free text.

## Live data

The site merges a live view of [vtessera](https://github.com/douglasdemaio/vtessera)
over the curated `vtessera` entry, fetching `GET /v1/agents` and
`GET /v1/metrics` at build time. Set `VTESSERA_BASE_URL` to enable it.

The live feed owns the entry's source tag, its `last_verified`, and the list of
registered agents. It does not own the service's own name, URL, or summary: the
agents it reports are vtessera's tenants, not vtessera, so their identity must
not overwrite the service listing.

Three things follow from that, and all three are tested:

- **No service, no snapshot** — the live section is simply absent and the site
  publishes. This is a normal state, not an error.
- **Service unreachable, snapshot present** — the committed snapshot is used,
  its age is shown, and the build logs a warning.
- **Snapshot older than 14 days** — the usage banner is marked stale.

Snapshot age comes from the `fetchedAt` field inside the snapshot, not the
file's modification time. Git does not preserve mtimes, so a fresh clone would
otherwise make a year-old snapshot look minutes old and the banner would claim
fresh data that is not.

`refresh-live.yml` commits the snapshots daily. It is a no-op while
`VTESSERA_BASE_URL` is unset, and it commits only on change.

## Usage metrics

`GET /v1/metrics` reports totals derived from the public ledger: a trade counts
as delivered when a receipt exists, and disputed or cancelled counts are
terminal outcomes. Per-agent figures are keyed by `agentId`.

The site shows a banner of aggregate totals, and a per-agent badge on the
vtessera page once an agent has at least three recorded deliveries. Agent IDs
are used only to join data and are never rendered.

No analytics are collected here: no page views, referrers, IPs, or user agents,
and no third-party scripts.

## Discovery

The generator emits `robots.txt`, `sitemap.xml`, `llms.txt`, `agents.json`,
`/.well-known/agent-card.json`, and per-entry JSON-LD.

`robots.txt` allows retrieval and answer engines and disallows bulk training
crawlers, with each named group verified against vendor documentation. Under
RFC 9309 a named group wins over the wildcard, so the policy is explicit rather
than relying on the wildcard alone.
